# ask_human の質問規約

自律実行中に人間の判断が必要になったら、alir の `ask_human` MCP ツールで質問を登録する。
回答は非同期に返るので、質問後は回答を待たずにセッションを終える。

## 質問してよい条件

質問は不可逆または高影響の判断に限る。具体的には次のいずれかに該当する場合だけ質問する。

- DB スキーマや保存データ形式の変更
- 外部に公開される API・インターフェースの契約変更
- データやファイルの削除、破壊的なマイグレーション
- 課金・セキュリティ・個人情報に関わる変更
- Issue の記述と実装調査の結果が矛盾しており、どちらを正とするか決められない場合

これらに該当しない低影響の判断は質問しない。
推奨案を自分で選んで実装を進め、PR 本文の「判断ポイント」節にその判断と理由を記載する。
レビューで覆されたら直せばよい。

## 質問のフォーマット

回答者がスマホから選択肢をタップするだけで返せる形にする。

- **question**：判断してほしい内容。回答者が前提を調べ直さなくて済むだけの背景(何をしていて、何に突き当たったか)を含める。推奨する理由もここに書く。
- **options**：選択肢を 2〜4 個。それぞれ単独で読んで意味がわかる文にする。「はい」「いいえ」ではなく「スキーマを変更し、マイグレーションを追加する」のように書く。
- **recommended**：推奨する選択肢。options のいずれかと一致させる。
- **impact**：原則 `high`。`low` の判断はそもそも質問しない。
- **timeout_action**：無回答が続いたときの挙動。推奨案で進めて問題ない質問は `proceed_with_recommended`、人間の回答なしに進んではならない質問は `keep_parked`。
- **issue**：作業対象の Issue(`owner/repo#number`)。
- **session_id**：現在のセッション ID がわかる場合は渡す。

## 質問後の park の作法

質問を登録したら、そのセッションは次の手順で終える。

1. 作業ツリーを中途半端に残さない。ここまでの変更が自己完結しているならコミットし、していないなら破棄する。
2. 現状の要約(何を調べ、何がわかり、何を質問したか)を最終メッセージとして出力する。再開時のセッションはこの要約と回答を読んで続行する。
3. 回答を待つポーリングやスリープをしない。即座に終了する。
